# Game Mode: броски кубиков и проверки навыков

В этом руководстве вы узнаете, как бросать кубики в режиме Game Mode приложения Marinara Engine. Здесь описаны меню быстрых бросков, собственная запись броска и ограничения на такие броски. Также показано, как Game Master (ведущий игры) проводит проверку навыка против класса сложности DC.

## Броски кубиков

В чате Game Mode на панели ввода сообщения есть кнопка с кубиком. Наведите на нее курсор – появится всплывающая подсказка **Roll dice**. Нажмите эту кнопку, чтобы открыть меню быстрых бросков.

В меню восемь готовых бросков в одно нажатие:

| Вариант | Что бросается |
|---|---|
| d20 | один 20-гранный кубик |
| d6 | один 6-гранный кубик |
| 2d6 | два 6-гранных кубика |
| d10 | один 10-гранный кубик |
| d100 | один 100-гранный кубик |
| d4 | один 4-гранный кубик |
| d8 | один 8-гранный кубик |
| d12 | один 12-гранный кубик |

Чтобы сделать быстрый бросок:

1. Откройте панель ввода сообщения в чате Game Mode.
2. Нажмите кнопку с кубиком.
3. Выберите один из восьми вариантов, например **d20**.
4. В панели ввода появится небольшая плашка вида `🎲 d20`.

Бросок отправляется не сразу, а становится в очередь. Чтобы убрать бросок из очереди, нажмите на плашке кнопку очистки. Ее подсказка – **Clear queued roll**.

Кубики бросаются в момент отправки следующего сообщения. Результат приложение добавляет в конец сообщения отдельной пометкой. Один кубик без бонуса выглядит так:

```
[dice: d20 = 14]
```

Бросок нескольких кубиков или бросок с бонусом показывает еще и слагаемые:

```
[dice: 3d8+2 = 18 (4, 6, 6 +2)]
```

Game Master читает эту пометку и строит свое описание вокруг результата.

Если Game Master делает несколько бросков за ход, каждая карточка броска занимает отдельное место в очереди. Закройте карточку, чтобы увидеть следующую. Все броски сохраняются в активном свайпе (альтернативном ответе) этого хода и остаются в **Logs** (журнале) после перезагрузки. Продолжение хода сохраняет прежние броски; повторная генерация создает отдельный набор для нового свайпа.

Game Master также может запросить бросок в повествовании через `[dice: 3d8+2]`. Движок предоставляет реальные числа и показывает ту же анимированную карточку. Это работает и с подключениями, поддерживающими только текст, включая подписки Claude и Grok. Используются те же обозначения и ограничения, что и в меню костей.

## Собственная запись броска

В меню кубиков есть и текстовое поле для собственного броска. Оно принимает стандартную запись `NdM`. Здесь `N` – сколько кубиков бросить, а `M` – сколько у каждого граней. В конце можно добавить бонус или штраф.

Подсказка в поле показывает пример: `3d8+2`. Это значит – бросить три 8-гранных кубика и прибавить к сумме 2.

Чтобы задать свой бросок:

1. Нажмите кнопку с кубиком, чтобы открыть меню.
2. Введите запись в текстовое поле, например `2d6+1`.
3. Нажмите Enter или маленькую кнопку с бумажным самолетиком (отправка) рядом с полем.
4. Бросок встанет в очередь плашкой и будет готов к отправке.

Еще несколько примеров, которые можно ввести:

- `d20` – один 20-гранный кубик.
- `4d8-1` – четыре 8-гранных кубика минус 1.
- `2d6+3` – два 6-гранных кубика плюс 3.

Есть два жестких ограничения: за раз можно бросить не больше 100 кубиков, а у каждого кубика может быть не больше 1000 граней. Если запросить больше, приложение сокращает запрос до этих пределов, а не отклоняет его. Карточка результата показывает сокращенную запись: ввод `500d6` дает карточку `100d6` для ста действительно брошенных кубиков. Если текст не соответствует записи `NdM` или отдельной записи `dM`, например `d20`, бросок не выполняется, а ошибка указывает ожидаемый формат.

## Проверки навыков

Проверка навыка определяет, удастся ли вам что-то рискованное: подкрасться, заметить улику, убедить персонажа NPC (неигровой персонаж). Сами вы проверку не начинаете – ее объявляет Game Master прямо в своем описании. Приложение превращает объявление в анимированный бросок d20 и показывает баннер с результатом.

Проверка, запрошенная текстом, начинается с попытки действия. Движок определяет результаты бросков, затем делает один дополнительный запрос к модели с реальными результатами, чтобы Game Master завершил описание исхода в том же ходе. Это также исправляет черновик, в котором исход был угадан до броска. Дополнительный запрос повторно отправляет промпт и расходует больше входных и выходных токенов. Если он завершается ошибкой, ход сохраняет полученные результаты без угаданного или неполного описания исхода. На ходе остается уведомление с кнопкой **Regenerate turn** (перегенерировать ход), в том числе после перезагрузки чата.

Отключите **Narrate dice outcomes immediately** (сразу описывать результаты бросков) в **Chat Settings → Function Calling** (настройки чата → вызов функций), чтобы сохранить реальные результаты для следующего хода без дополнительного запроса. По умолчанию эта настройка включена. Запросы, в которых не было реальных бросков, никогда не запускают дополнительное описание результатов.

При подключении с поддержкой инструмента бросков Game Master может получить реальный результат во время генерации. Карточка появляется сразу после ответа инструмента; завершенная проверка сохраняет этот результат без повторного броска. Каждая разрешенная проверка навыка получает отдельный баннер после карточек бросков в очереди.

На баннере видны навык и целевое число, например **Stealth Check** и рядом **DC 15**. DC – это Difficulty Class, класс сложности: число, которого бросок должен достичь или превысить.

### Как определяется результат

При проверке бросается один 20-гранный кубик, а к результату прибавляются два модификатора:

- Модификатор навыка – от уровня навыка, который игра ведет для вашего персонажа. Если уровня для этого навыка еще нет, модификатор равен 0.
- Модификатор характеристики – от той характеристики, которая отвечает за этот навык.

Бросок кубика вместе с двумя модификаторами дает итог. Если итог достигает DC или превышает его, проверка пройдена. Если итога не хватает, проверка провалена. Характеристика для каждого навыка выбирается автоматически. Например, Stealth опирается на Dexterity, Perception – на Wisdom, а Persuasion – на Charisma. Незнакомый приложению навык считается по Intelligence.

### Критический успех и критический провал

Два броска отменяют всю математику:

- Натуральная 20 (на самом кубике выпало 20) – это **CRITICAL SUCCESS** (критический успех). Такая проверка проходит всегда, даже при высоком DC.
- Натуральная 1 (на самом кубике выпала 1) – это **CRITICAL FAILURE** (критический провал). Такая проверка провалена всегда, даже с большими модификаторами.

Баннер показывает один из четырех итогов: **CRITICAL SUCCESS**, **SUCCESS** (успех), **FAILURE** (провал) или **CRITICAL FAILURE**.

### Другие системы костей

Game Master может указать другую запись, например `[skill_check: skill="Endurance" dc="12" dice="3d6+2"]`. Такие проверки используют фиксированный модификатор из записи вместо модификаторов d20 из листа персонажа и успешны, когда сумма достигает DC. Правила натуральной 1 и натуральной 20 действуют только для стандартной проверки d20, описанной выше.

Пулы успехов должны указывать и порог для отдельной кости, и нужное число успехов: `[skill_check: skill="Intimidation" dc="4" dice="6d10" resolution="successes" threshold="6"]` бросает шесть d10, считает каждую кость с результатом не меньше 6 один раз и дает успех при наличии хотя бы четырех успехов. Движок не угадывает отсутствующий порог и не реализует взрывающиеся кости, правила botch или другие особые правила пулов. Пул без корректного порога остается неразрешенным, а выдуманные моделью числа удаляются.

Неподдерживаемые запросы, такие как `4d6kh3`, `3d6!` или `4dF`, не выполняются. Движок записывает неподдерживаемую запись в лог и удаляет выдуманные числа из записей проверок. Эти исходы остаются неопределенными; движок не заменяет систему костей молча.

### Преимущество и помеха

Game Master может объявить проверку с преимуществом или с помехой. Одновременно и то и другое к одной проверке не применяется.

- С преимуществом приложение бросает два 20-гранных кубика и берет больший результат.
- С помехой приложение бросает два кубика и берет меньший результат.

Если Game Master запросит оба режима одновременно, приложение оставит проверку без обработки, а не станет угадывать намерение, поэтому баннер для нее не появится.

Когда включено одно из двух, баннер показывает этот режим рядом с DC и отмечает, какой кубик пошел в счет.

### Свой бросок заранее

Свой `d20` можно поставить в очередь из меню кубиков заранее, до самой проверки. Тогда проверка навыка возьмет выпавшее у вас число вместо нового броска. Модификаторы навыка и характеристики все равно прибавляются к нему.

## Игры с набором правил

Набор выбирается один раз в **Rules** при создании игры; см. [Выбор правил](getting-started.md#choosing-rules). Без набора действуют описанные выше правила, включая простые пулы успехов без взрывных костей и других особых правил.

- GM указывает навык или спасбросок и сложность по шкале набора. Она может выходить за 1–40; резервное разрешение ожидающей проверки в сохраненном ходе по-прежнему ограничено 1–40.
- Движок бросает кости набора. Модификатор берется из его листа: характеристика, подготовка (кратность бонуса мастерства, фиксированное значение или оба) и дополнительный бонус. Встроенные характеристики и бонусы навыков не используются.
- `who="Name"` выбирает спутника; без поля подразумевается игрок. Спутник без листа использует значения по умолчанию. Неизвестное или неоднозначное имя дает бросок без модификатора. Имя персоны всегда означает игрока, даже при совпадении с именем спутника. Чужой лист никогда не подставляется.
- Натуральные результаты определяет набор. В 5e (SRD 5.1) натуральные 20 и 1 не имеют особого действия для проверок и спасбросков; даже 20 может не хватить.
- Числа, записанные GM, проверяются. Неверный модификатор, число или тип костей, выбранная кость либо неподдерживаемый натуральный результат заменяются новым броском.
- Заранее сделанный ручной бросок применяется только к одной d20. Другие кости, например 2d6 или пул, бросаются заново.
- `with="Ability"` разрешает другую характеристику, объявленную набором; неизвестная игнорируется. Метки бросков могут называть характеристики, навыки, спасброски и `PROF`, если есть бонус мастерства.
- Отсутствующий или устаревший пакет оставляет проверку ожидающей, без чисел. Движок не подменяет систему правил. Ресурсы, состояния и отдых описаны в разделе [Лист набора правил](party-and-npcs.md#the-ruleset-sheet).

### Наборы с пулами костей

Значение листа определяет количество костей: характеристика 3 и навык 2 дают пять костей. Редактор и контекст GM показывают "5 dice" вместо "+5". Сложность – нужное число успехов, например три, а не сумма 15.

Набор задает порог, двойные успехи, взрывы, отмену успехов низкими результатами, критические провалы и исключительные успехи. Карточка показывает все кости, выделяет успешные и сравнивает их число с целью. Большие пулы переносятся на новые строки, не уменьшая кости и не показывая вымышленную сумму.

GM может менять порог отдельной кости или размер пула только в пределах набора. Придуманные моделью результаты всегда заменяются настоящим броском. Преимущество, заранее сделанные ручные броски и предварительный показ d20 для GM не применяются: пул бросается без предварительного показа.
